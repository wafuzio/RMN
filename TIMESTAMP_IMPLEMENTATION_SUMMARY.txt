================================================================================
HOW IT WORKS
================================================================================

1. BACKEND RETURNS UTC (ISO Z)
   Card structure:
   {
     "timestamp": "2025-10-27T02:56:54Z",  // UTC
     "timestamp_ms": 1730000214000          // Epoch milliseconds
   }

2. FRONTEND RENDERS IN VIEWER'S LOCAL TIMEZONE
   Same timestamp displays differently based on viewer location:
   - Central Time (UTC-5): "Oct 26, 2025 9:56 PM"
   - Eastern Time (UTC-4): "Oct 26, 2025 10:56 PM"

3. NO MORE GRID/MODAL MISMATCH
   Both use the same formatter → same display

================================================================================
FRONTEND USAGE
================================================================================

Import the utility:
  import { formatLocal } from "@/lib/date"

Use in Grid:
  <div>{formatLocal(card.timestamp)}</div>

Use in Modal:
  <div>{formatLocal(card.timestamp)}</div>

Other utilities available:
  - formatLocalDate(iso)     // Short date only
  - formatRelative(iso)      // "2 hours ago"
  - getLocalMTDRange()       // MTD boundaries for filtering
  - getLocalYTDRange()       // YTD boundaries for filtering
  - getLocalCustomRange()    // Custom date range

================================================================================
DATE FILTERING (MTD/YTD)
================================================================================

Frontend computes local range and converts to UTC for API:

  import { getLocalMTDRange } from "@/lib/date"
  
  const { startIsoUtc, endIsoUtc } = getLocalMTDRange()
  fetch(`/api/ads/cards?start=${startIsoUtc}&end=${endIsoUtc}`)

Backend compares UTC timestamps → accurate filtering!
